# Beacon

An interactive security lab about prompt injection and file access. Add an
instruction to a fictional leave policy, then compare what happens when an
assistant can read both the policy and payroll versus just the policy.

Answers are scripted, not generated by a live model. Access checks illustrate
permissions; they do not demonstrate AWS IAM enforcement. No cloud account,
credentials, or paid inference are needed.

Built with React, TypeScript, Vite, Tailwind, React Flow, and adapted React Bits
components. The optional local service uses Python and FastAPI.

## Try the browser demo

Requires Node.js 22.22.2+ within Node 22 LTS, Node 24.15+, or Node 26+.

The showcase build runs entirely in the browser, without a backend or sign-in:

```bash
cd frontend
npm ci
npm run build:demo
npm run preview
```

Open **http://127.0.0.1:4173**. For development with live reloading, use
`npm run dev -- --mode demo` instead.

To publish this build, follow the [Cloudflare Pages guide](docs/public-demo.md).
The website can be public while the GitHub repository stays private. A live
showcase URL has not been configured yet.

### What to try

1. Click **Run comparison** with the original policy. Neither version requests
   payroll, so both show **No private file requested**.
2. Select **Hidden instruction** and run again. **Too much access** exposes the
   fictional payroll; **Limited access** shows **Private file blocked**.
3. Open **Access details** to separate file retrieval from disclosure in the
   answer. **Inspect run** shows the recorded events and access graph.
4. Under **Options**, try ignoring the instruction or reading the file without
   including it in the answer. Reading confidential data is still a problem even
   when the final answer does not reveal it.
5. Export a JSON replay or Markdown report. Imported reports are labeled
   **source not verified**; a document hash does not prove authenticity.

The walkthrough prepares an example without running it. Light/dark themes,
keyboard controls, mobile layouts, and reduced-motion alternatives are included.

## Run with the local API

The default development and production builds use the Python API. API errors
never silently switch to browser simulation.

From the project root, start the service:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m uvicorn beacon.api:app --host 127.0.0.1 --port 8000
```

In another terminal:

```bash
cd frontend
npm ci
npm run dev
```

Open **http://localhost:5173**. Vite proxies `/api` to the loopback service. API
documentation is at **http://127.0.0.1:8000/api/docs**.

For reproducible Python verification, install `requirements-dev.lock`, then
install the project with `pip install -e . --no-deps` using the virtual environment.

## Local CLI

Run the Python simulation without a browser or API server:

```bash
.venv/bin/python -m beacon --scenario injected
.venv/bin/python -m beacon --scenario injected --behavior retrieve_only
.venv/bin/python -m beacon --policy data/leave-policy-clean.txt --target protected
.venv/bin/python -m beacon --scenario injected --format json > beacon-simulation.json
```

The JSON output can be imported into either interface mode. Use an unused output
filename to avoid overwriting an existing report.

## Check the project

```bash
.venv/bin/python -m pytest
.venv/bin/python scripts/check-browser-parity.py --check
node --test tests/deployment/navigation.test.mjs
```

From `frontend/`:

```bash
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:demo
```

The API browser suite starts the local service; the demo suite tests a static
build with the Pages security headers and no API. Parity tests compare the
browser engine with the Python engine. Run browser suites separately from Docker
network setup to avoid transient browser network errors.

## Data and deployment

- Use fictional data only. All bundled samples, including payroll, are public
  in the browser demo. Its permission checks are not a security boundary against
  someone inspecting or modifying their own browser.
- Documents and captures stay in memory. Only the theme preference is persisted.
  API mode sends inputs to the local service; browser mode does not upload them.
- Exports include the captured document, question, and answers. Credential-pattern
  guards do not catch every secret or personal detail.
- Do not publish the development API. Server-side hosting uses the separate
  [invite-only HTTPS/SSO deployment](docs/deployment.md).
- AWS, Bedrock, S3 uploads, and cloud audit evidence are not implemented.
